[![CI](https://github.com/Ifasola34/vrt1-spec/actions/workflows/ci.yml/badge.svg)](https://github.com/Ifasola34/vrt1-spec/actions/workflows/ci.yml)

**Formal protocol specification for VRT1** — the Bitcoin-anchored attestation protocol implemented by [VERITAS](https://github.com/Ifasola34/veritas) and its ecosystem.

This repository contains:

- **[`spec/VRT1.md`](spec/VRT1.md)** — the specification document (~440 lines, 14 numbered sections, RFC 2119 language).
- **[`test-vectors/`](test-vectors/)** — 7 canonical JSON test vectors implementations can reproduce byte-for-byte.
- **[`tests/`](tests/)** — generator (`generate_vectors.py`) that produces the vectors from the reference implementation, plus a stability test that asserts regenerated bytes match the checked-in copies.

---

## Who this is for

| Audience | Why read this |
|---|---|
| **Implementers** building VRT1 from scratch in another language | The spec gives exact byte layouts, JSON canonicalization rules, signing digests, and the verification algorithm. The test vectors let you validate your implementation produces the same bytes as the reference. |
| **Security auditors** reviewing a VRT1 deployment | The "Security Considerations" section enumerates the threat model and what each layer defends against. Each spec section calls out which findings from the reference implementation's 3-round code-review cycle drove the current rules. |
| **Grant reviewers + protocol researchers** | Concise, citable artifact (single file, 14 sections, all references in Section 14) you can read without running anything. |
| **Lightning / Bitcoin / Nostr / L402 implementers** | The cross-references explain exactly how VRT1 composes BIP-340, RFC-6962, NIP-01, NIP-33, and L402 into one trust path. |

## Test vectors

7 JSON files under [`test-vectors/`](test-vectors/), each declaring which spec section it covers:

| File | Section | What it locks down |
|---|---|---|
| `attestation.json` | 3 | Canonical signed attestation: payload, canonical bytes, digest, sig |
| `merkle.json` | 4 | Trees of size 1, 2, 3, 4, 5, 7, 8 with inclusion proofs for every leaf |
| `op_return.json` | 5 | 49-byte payload roundtrip (build + parse) |
| `nostr_attestation_event.json` | 7 | Kind-30078 event with event id + signature |
| `nostr_checkpoint_event.json` | 6 | Kind-30079 event with parsed signed content |
| `agent_action.json` | 8 | Signed agent action (kind 1990) |
| `kwh_measurement.json` | 9 | Signed kWh measurement (kind 1991) |

Vectors are produced from **fixed demo private keys** + **fixed `ts`** + **fixed BIP-340 `aux_rand` = 32 zero bytes**, so any compliant implementation reproduces the same bytes deterministically.

The keys in the vectors (`1111…`, `2222…`, etc.) are PUBLICLY KNOWN AND DEMO-ONLY. Never use them in production.

## Verify your implementation

If you're building a VRT1 implementation, the smoke test is:

1. Pick a test vector (e.g. `attestation.json`).
2. Reconstruct the canonical payload from the listed fields.
3. Compute `tagged_hash("VRT1/attestation", canonical_bytes)`. It must equal `attestation_digest_hex`.
4. Verify the BIP-340 Schnorr signature in `sig_hex` against `oracle_pubkey_xonly_hex` and the digest. It must return `True`.

Repeat for each vector. If all 7 verify, your implementation correctly handles the wire formats and signing digests specified in VRT1.1.

## Stability guarantee

The CI workflow in this repo:

1. Installs the reference implementation (`veritas`, `vrt1-agents`, `vrt1-kwh`) from their `main` branches.
2. Reruns `tests/generate_vectors.py`.
3. Asserts the regenerated vectors are byte-identical to the checked-in copies.

If they ever diverge, the CI goes red. This means:

- **Accidental protocol drift** in the reference implementation is caught before it's released.
- **Intentional protocol changes** (a bump from VRT1.1 → VRT1.2) require regenerating vectors in the same commit as the implementation change. There's no quiet way to change the wire format.

```bash
$ pytest -q
4 passed in 0.05s
```

## Status

VRT1 is currently at **version 1, status: Draft**. The reference implementation passes 401 unit tests across 5 repos + an end-to-end integration test in [`vrt1-demo`](https://github.com/Ifasola34/vrt1-demo). Open questions and roadmap items for VRT1.2 are listed in Appendix B of the spec.
